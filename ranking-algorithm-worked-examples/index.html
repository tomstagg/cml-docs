CML ranking algorithm — balanced scorecard worked examples¶

Read-only analysis. Generated by driving the live runtime path (app.services.search.search_firms) against the local cml_db for six intake scenarios (Annex One §5.3, post-#55/#83), then re-deriving every intermediate with the same primitive functions and cross-checking against the engine output. No runtime code was changed to produce this document.

How each factor score is produced¶

All six factor scores are 0–100, held at full precision; only the final weighted overall is rounded to an integer for display (search.py).

Factor Type How it is scored at runtime Source
Reputation Relative (min–max) Stored adjusted_reputation_value (ARV) per firm, then (ARV − ARV_min)/(ARV_max − ARV_min)×100 across the priced results set. ARV spec = rating×(1+k·ln(reviews+1)), k=0.025 (Annex One §5.6). All-equal → 50. ranking.normalise_reputation
Price Relative (min–max) Total Effective Price per firm, then (P_max − P)/(P_max − P_min)×100 (lower price → higher score). All-equal → 50. price_calc + ranking.normalise_price
Complaints Absolute Pre-computed in the Master Export workbook (base 100 − Σ LeO deductions), stored on the firm; consumed verbatim. Default 100 if no summary. organisation.complaints_summary.score
Regulatory Absolute Pre-computed (base 100 − Σ SRA/SDT deductions, no floor), stored; consumed verbatim. SRA intervention → firm excluded upstream. Default 100. organisation.regulatory_summary.score
Distance Absolute (banded, miles) Geodesic miles from user postcode to nearest office, then banded: 0–2→100, 2–5→95, 5–10→85, 10–15→70, 15–25→50, 25–40→25, 40+→10. Excluded if no postcode. search.haversine_km + ranking.score_distance
Offices Absolute (banded) 1→70, 2–3→78, 4–6→85, 7–10→90, 11–20→95, 21+→100. ranking.score_offices

Balanced weights (scorecard.SCORECARDS['balanced']): Reputation 27, Price 23, Complaints 15, Regulatory 15, Distance 10, Offices 10. Overall = Σ(score×weight)/100. When the user gives no postcode, distance weight → 0 and the remaining five are proportionally rescaled to sum to 100 (resolve_weights).

Firms without a usable quote for the intake (no price card, price_type=no_data, or every anchor withheld) are ranked after all priced firms, using the remaining five factors rescaled to 100 (price omitted) — see search.py's price-less path (issue #50). They are never eligible for the top-5 contactable set regardless of enrolment.

Sequencing (§3.5): the full WMCA market is ranked first; the top-5 contactable (enrolled + active-in-pilot, with a usable quote) firms are then extracted from that single ranking — enrolled firms are never ranked separately.

Tie-break (§11): overall → reputation → complaints → regulatory → price → distance → offices → alphabetical.

Observations from the data¶

These fall out of the six worked scenarios above; they describe current behaviour, not bugs to fix here.

  1. The stored Adjusted Reputation Value still does not match the Annex One §5.6 formula. Every worked calculation above shows the stored ARV below rating×(1+0.025·ln(reviews+1)) (e.g. Firm 153: stored 5.3648 vs spec 5.5778; Firm 001: stored 4.8462 vs spec 5.1624). scripts/validate_factor_scores.py confirms this is systematic: all 161 firms with a recorded rating diverge beyond the 0.01 tolerance. This is the same previously-flagged founder decision, not new.
  2. Roughly half the 190-firm market has no usable quote for any single-tenure intake. 95/190 firms price a freehold purchase (A, D, E, F), 89/190 a leasehold purchase (B), 93/190 a freehold sale (C) — the remainder have no price card, price_type=no_data, or every anchor "withheld" in the 07.07.26 export. Price-less firms rank after all priced firms on the remaining five factors rescaled to 100, and are never eligible for top-5 contactable (issue #50).
  3. Firm 004 (CML-004) — enrolled and active-in-pilot — is priceless in every scenario tested. Its price card has every anchor marked "withheld" for all four tenure/side combinations in the current export (a genuine data gap, not an engine bug), so despite scoring a competitive 86–88 on the remaining five factors it never appears in top-5 contactable, leaving only 5 of the 6 enrolled+active firms eligible per scenario.
  4. Distance is flat for a Birmingham-centre postcode. B1 2JB puts nearly every priced firm inside the 0–2mi band (score 100) in scenarios A/B/C/E/F, so distance barely separates firms for this postcode; scenario D shows the mechanical alternative — with no postcode, distance weight (10) is stripped and the other five weights rescale by ÷0.9 (27→30, 23→25.556, 15→16.667 ×2, 10→11.111), reproduced exactly in that scenario's worked calculation.
  5. The price-priority scorecard (E) visibly reorders the market. Reputation-heavy firms from the balanced-scorecard top 20 (Firm 153, Firm 073) are joined at the top by price-competitive firms (Firm 177, Firm 168) that ranked lower under balanced weights; Firm 064 — the only top-20 firm carrying a real regulatory deduction (60.00, a Band-C-equivalent finding) — still reaches rank 19 purely because Price is weighted 40.
  6. Scenario F's CPS pricing items (#55/#83) are live and visible in a real quote. Poole Alcock's breakdown shows Solar Panels, Freehold Management Company and Existing Tenancy each adding £150.00 to the £2,100.00 fees subtotal (on top of the pre-existing Acting for Lender £200.00) — £450.00 of new modifier value that would have been silently dropped before #55. Firm 001' verified price card, by contrast, has all three of those modifiers priced at £0.00, so it was swapped out for Firm 002 as the worked firm for this scenario (see the script's scenario-F comment).
  7. No genuine tie-break example arose from these six scenarios. Many firms share the same rounded integer overall score (expected, on a 0–100 integer display scale with ~95 priced firms per scenario), but ranking always sorts on the full-precision raw overall first — no two firms shared an identical raw overall in any scenario, so the §11 tie-break chain (reputation → complaints → regulatory → price → distance → offices → alphabetical) was never actually invoked to break a tie here. It remains pinned by dedicated unit tests in tests/unit/test_scorecard.py.

Deviations¶

None. Every worked calculation in this document (12 across the six scenarios, plus the scenario-A baseline hand re-derivation — 13 checks in all) reproduced the live engine's rounded overall score exactly — see the "✓ matches" annotation on each. scripts/generate_worked_examples.py computes every number in this document directly from search_firms()'s return value (or, for the hand re-derivation, from the same per-firm factor scores summed by the documented formula), so there is no separate manual-transcription step where a number could have drifted from the engine.
